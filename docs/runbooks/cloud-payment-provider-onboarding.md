# 云端支付服务商接入与撤销操作手册

日期：2026-08-06  
适用范围：CXPAY 云端个人码监控连接器及对应服务商

## 1. 目的

本手册用于规范云端支付服务商的评估、密钥建立、插件签名、安装、启用、轮换、停用和撤销过程。

本手册不适用于支付宝或微信官方商户 API 驱动。官方商户支付使用独立的应用密钥、证书或商户授权令牌流程。

## 2. 不可绕过的前提

服务商方案必须符合 `ADR-PAY-001：云端支付凭据隔离`：

- 支付账号 Cookie、网页登录 Token 和可复用会话只能存在云端；
- CXPAY 不提供手工粘贴 Cookie 的入口；
- CXPAY 只保存不可用于登录的 `account_id`；
- 本地插件只做协议适配；
- 所有云端请求使用公共安全 HTTP 客户端；
- 回调必须签名、幂等和防重放。

任一条件不满足时，禁止进入安装或生产启用阶段。

## 3. 服务商准入材料

服务商至少提供：

- 法人或组织身份信息；
- 服务域名及所有 API 主机名；
- 数据存储地区和基础设施说明；
- 支付账号凭据加密和密钥管理说明；
- 多租户隔离设计；
- 日志和审计策略；
- 回调重试策略；
- 数据保留和销毁策略；
- 安全事件联系人；
- 变更和停服通知机制；
- 插件源码及构建说明；
- 发布者签名公钥。

不得只提供编译包而拒绝源码审查。

## 4. 安全评估

### 4.1 云端凭据库

确认：

- Cookie 和 Token 使用独立加密密钥；
- 密钥与数据库分离；
- 不在日志中记录凭据；
- 租户之间不能读取彼此凭据；
- 凭据访问有审计；
- 支持主动撤销和安全销毁；
- 备份同样加密；
- 运维人员访问受最小权限和审批控制。

### 4.2 API 和网络

确认：

- API 仅使用 HTTPS 443；
- 域名固定且不使用动态任意回调地址；
- TLS 证书有效；
- 不要求 CXPAY 跟随重定向；
- 请求和响应均签名；
- nonce 和时间戳防重放；
- 响应体大小有上限；
- 服务端不会向 CXPAY 返回 Cookie；
- 服务域名的 DNS 变更有审批和通知。

### 4.3 到账可信性

确认：

- 订单必须先登记；
- 账单事件只能匹配一个订单；
- 金额和账号必须一致；
- 到账事件具有全局唯一 `event_id`；
- 重复事件返回原结果；
- 异常账单进入审查队列，不直接核销；
- 服务商保留可追溯审计。

## 5. 发布者信任建立

### 5.1 公钥文件

将审核通过的发布者 RSA 公钥放入 CXPAY 受信任密钥目录，文件名必须与 manifest 的 `publisher` 一致：

```text
{publisher}.pem
```

例如：

```text
cxpay.official.pem
```

要求：

- 公钥通过独立渠道核验指纹；
- 不从插件包本身提取并自动信任；
- 私钥不得进入 CXPAY；
- 公钥变更必须有双人复核和审计。

### 5.2 默认信任策略

第一阶段默认只信任：

```text
cxpay.official
```

新增第三方发布者必须完成代码审查和独立批准。

## 6. 插件包构建

官方构建命令：

```bash
php tools/plugin/build.php \
  plugins-src/<plugin-slug> \
  /secure/private.pem \
  dist/<plugin-slug>.cxpay-plugin
```

构建前检查：

- manifest 声明 `runtime_type=cloud_connector`；
- manifest 声明 `credential_boundary=cloud_only`；
- `outbound_hosts` 是精确主机名；
- `secret_config` 不包含支付账号登录凭据；
- 源码中没有 Cookie 输入和中转逻辑；
- 驱动入口实现 `PaymentDriverInterface`；
- 测试通过；
- 构建环境不含无关私钥或生产配置。

构建后保存：

- 插件包 SHA-256；
- manifest；
- 签名文件；
- 源码提交 SHA；
- 构建人和构建时间；
- 测试报告。

## 7. CXPAY 安装

安装前：

1. 备份插件注册表；
2. 确认目标 CXPAY 版本满足要求；
3. 核对插件包 SHA-256；
4. 核对发布者和公钥；
5. 检查 manifest 权限；
6. 确认目标服务域名已批准；
7. 确认生产工作树无计划外修改。

安装器必须验证：

- ZIP 格式和大小；
- 路径安全；
- 文件数量和单文件大小；
- 文件扩展名；
- 文件哈希；
- 发布者 RSA 签名；
- 驱动标识未被永久移除；
- 驱动入口存在。

安装后插件保持停用。

## 8. 本地连接密钥建立

每个 CXPAY 实例分配独立：

```text
client_id
client_secret
callback_secret
```

禁止多个客户或多个 CXPAY 实例共享同一密钥。

密钥要求：

- 使用密码学安全随机生成；
- 长度至少 32 字节等效强度；
- 通过安全渠道交付；
- 在 CXPAY 使用敏感配置加密保存；
- 在云端绑定明确租户和允许权限；
- 不通过聊天、工单正文或普通邮件传递；
- 不写入 Git。

## 9. 服务地址配置

配置前确认：

- scheme 为 HTTPS；
- 端口为 443；
- 主机与 manifest `outbound_hosts` 精确匹配；
- 不使用 IP 地址；
- URL 不含用户名和密码；
- DNS 所有 A/AAAA 结果均为公网地址；
- 云端证书主机名匹配。

不得配置临时隧道、内网地址、localhost 或任意自定义端口作为生产服务地址。

## 10. 授权验收

创建停用状态的通道，然后：

1. CXPAY 请求云端创建授权会话；
2. 云端返回短期 `session_id`、`qr_url` 和 `expires_at`；
3. CXPAY 展示二维码；
4. 商户使用支付 App 扫码；
5. 云端保存登录态；
6. CXPAY 轮询得到 `CONFIRMED` 和不可登录 `account_id`；
7. CXPAY 保存 `account_id`；
8. 授权响应、数据库、Redis 和日志中确认没有 Cookie。

授权失败、过期和重新授权也必须测试。

## 11. 支付验收

至少完成：

- 订单登记成功后才展示固定收款码；
- 登记失败不展示收款码；
- 相同订单重复登记幂等；
- 参数变化触发幂等冲突；
- 小额真实到账正确匹配；
- 回调签名正确；
- 错误签名被拒绝；
- 错误金额被拒绝；
- 错误账号被拒绝；
- 重复 `event_id` 不重复核销；
- 重复 nonce 被拒绝；
- 丢失回调可通过订单查询恢复；
- 异常账单进入审查队列。

## 12. 生产启用审批

生产启用记录至少包含：

- 插件 ID 和版本；
- 发布者；
- 源码提交 SHA；
- 插件包 SHA-256；
- 服务商和域名；
- 测试负责人；
- 安全评估负责人；
- 批准人；
- 启用时间；
- 初始限额；
- 回滚负责人。

首次启用采用：

- 单商户；
- 单通道；
- 低单笔和低日限额；
- 实时观察回调和异常事件；
- 明确信任提示。

## 13. 密钥轮换

### 13.1 回调密钥

轮换流程：

1. 云端生成新密钥；
2. CXPAY 将当前密钥移入 `callback_secret_previous`；
3. CXPAY 配置新 `callback_secret`；
4. 云端切换签名密钥；
5. 验证新密钥回调；
6. 观察宽限期；
7. 清空旧密钥；
8. 记录审计事件。

宽限期内新旧密钥都可验签，但不得无限期保留旧密钥。

### 13.2 请求密钥

`client_secret` 轮换应使用双密钥版本或明确切换窗口，避免请求全部中断。不得在结果不确定的订单登记过程中改变业务号。

## 14. 插件升级和回滚

升级前：

- 阅读变更说明；
- 对比 manifest 权限；
- 检查是否新增服务域名；
- 检查是否新增配置字段；
- 重新执行 Cookie 隔离扫描；
- 完成测试环境验收。

插件必须先停用才能切换活动版本。

回滚后：

- 验证驱动能加载；
- 验证订单查询；
- 验证回调签名；
- 检查是否存在新版本已产生但旧版本不识别的状态；
- 不删除历史事件和审计记录。

## 15. 紧急停用

以下情况立即停用插件和相关通道：

- 发现 Cookie 进入 CXPAY；
- 服务商密钥泄露；
- 发布者私钥疑似泄露；
- 回调可伪造或防重放失效；
- 服务域名被劫持；
- 云端账号隔离失效；
- 大量错误匹配或重复核销尝试；
- 服务商无法提供审计。

紧急动作：

1. 停用插件；
2. 将相关通道离线；
3. 撤销 CXPAY 客户端密钥；
4. 停止云端回调；
5. 保留日志和事件证据；
6. 审查待支付订单；
7. 审查近期到账事件；
8. 通知受影响商户；
9. 完成事件复盘后再决定恢复。

不得通过删除日志、注册表或订单记录来“清理现场”。

## 16. 服务商撤销

计划撤销时：

1. 停止创建新授权；
2. 停止创建新订单；
3. 等待或处理现有订单；
4. 导出非敏感审计记录；
5. 撤销所有 CXPAY 客户端密钥；
6. 要求云端销毁 Cookie 和 Token；
7. 获取销毁确认；
8. 停用并卸载插件；
9. 从批准域名列表移除服务商；
10. 视风险决定是否撤销发布者公钥信任。

CXPAY 不接收云端 Cookie 备份，也不将登录态迁移给另一服务商。新服务商必须重新扫码授权。

## 17. 证据留存

保留：

- 审批记录；
- 插件包和哈希；
- 发布者公钥指纹；
- 源码提交 SHA；
- 测试报告；
- 域名和证书核验记录；
- 密钥轮换记录；
- 启用、停用、升级和回滚事件；
- 安全事件复盘。

不得留存：

- 支付账号 Cookie；
- 网页登录 Token；
- 完整接口密钥明文；
- 可复用二维码授权会话；
- 商户支付账号密码。
