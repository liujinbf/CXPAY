# 外部易支付上游能力收敛设计

- 日期：2026-08-05
- 状态：已批准
- 目标分支：`fix/p0-hardening`
- 替代驱动：`qqpay_epay`
- 保留驱动：`epay_generic`

## 1. 背景

CXPAY 本身向下游商户提供易支付兼容接口，同时也包含将订单转发给第三方易支付平台的上游驱动。

这两种能力使用相似协议，但角色不同：

```text
下游兼容接口：
商户 -> CXPAY -> 本地或直接支付通道

外部上游适配器：
商户 -> CXPAY -> 第三方易支付平台 -> 支付渠道
```

当前存在两个外部易支付上游驱动：

- `epay_generic`
- `qqpay_epay`

`epay_generic` 已支持 `alipay`、`wxpay` 和 `qqpay` 三种支付类型；`qqpay_epay` 只是在相同协议上固定使用 `qqpay`，属于重复实现。

## 2. 目标

本次改动完成以下目标：

1. 永久移除重复的 `qqpay_epay` 驱动。
2. 保留 `epay_generic` 作为唯一的外部易支付上游适配器。
3. 将 `epay_generic` 明确标记为可选上游能力。
4. 默认不创建、不启用外部易支付上游通道。
5. 阻止外部易支付上游指向当前 CXPAY 实例。
6. 安全归档并清理可能存在的 `qqpay_epay` 活动通道。
7. 保留历史订单和账单中的通道引用。

## 3. 非目标

本次不处理以下事项：

- 不将 `epay_generic` 改造成可安装插件。
- 不删除 CXPAY 对下游商户提供的易支付兼容接口。
- 不自动创建任何 `epay_generic` 通道实例。
- 不自动迁移 `qqpay_epay` 的 PID、KEY 或其他敏感配置。
- 不提供回环保护绕过开关。
- 不重构所有支付驱动的网络请求层。
- 不改变历史订单和历史账单中的 `channel_id`。

## 4. 驱动收敛

### 4.1 保留 `epay_generic`

`epay_generic` 继续作为系统内置驱动。

公开名称改为：

```text
外部易支付上游（可选）
```

公开描述改为：

```text
将 CXPAY 订单转发给第三方易支付兼容平台；
不是 CXPAY 对下游商户提供的易支付接口。
```

继续支持：

- `submit.php` 页面跳转模式；
- `mapi.php` 服务端出码模式；
- `alipay`；
- `wxpay`；
- `qqpay`；
- 易支付 MD5 下单签名；
- 易支付 MD5 回调验签。

驱动存在不代表通道已经创建或启用。

### 4.2 永久移除 `qqpay_epay`

执行以下处理：

1. 删除 `app/payment/Drivers/QqpayEpay/`。
2. 将 `qqpay_epay` 加入 `RemovedPaymentDrivers`。
3. 阻止内置驱动发现重新加载该代码。
4. 阻止插件注册相同支付驱动代码。
5. 阻止管理员或商户保存新的 `qqpay_epay` 通道。
6. 从公开驱动列表和通道选择器中移除。
7. 从套餐 `allowed_channels` 中移除。
8. 由 `epay_generic` 的 `qqpay` 类型替代其功能。

本次完成后，公开底层驱动数量由 6 个变为 5 个。

## 5. 外部上游回环保护

### 5.1 组件边界

新增专用组件：

```text
app/payment/EpayUpstreamGuard.php
```

该组件只负责验证外部易支付上游地址，不改变其他出站 HTTP 请求的行为。

组件输入：

- 外部上游 `api_url`；
- 当前实例的 `APP_URL`；
- 当前服务的 `HOST`；
- 当前服务的 `PORT`。

组件返回规范化并验证后的目标信息：

```php
array{
    scheme: string,
    host: string,
    port: int,
    ip: string
}
```

验证失败时抛出明确的领域异常，调用方不得将安全错误当作普通网络错误吞掉。

### 5.2 失败关闭

以下任何条件成立时拒绝配置或下单：

1. `APP_URL` 未配置。
2. `APP_URL` 不是有效 HTTP(S) URL。
3. `api_url` 不是有效 HTTP(S) URL。
4. URL 包含用户名或密码。
5. 目标主机为空。
6. 目标为 `localhost`。
7. 目标使用环回、私网、链路本地或保留地址。
8. 目标 DNS 无法解析。
9. 目标 DNS 没有可验证的公网 A 或 AAAA 地址。
10. 目标主机名与 `APP_URL` 主机名相同。
11. 目标与 `APP_URL` 的有效端口相同，且解析 IP 集合存在交集。
12. 目标直接指向当前 `HOST:PORT`。
13. 目标端口不符合现有生产出站策略。

不增加环境变量或后台开关用于绕过这些规则。

### 5.3 地址规范化

比较前执行以下规范化：

- scheme 转为小写；
- host 转为小写；
- 移除 host 末尾的点；
- 未显式提供端口时，HTTP 使用 80，HTTPS 使用 443；
- IP 使用规范化字符串表示；
- A 和 AAAA 记录去重后参与比较。

同一主机名的不同路径仍视为同一个上游目标。

### 5.4 DNS 与请求绑定

验证阶段解析全部可用 A 和 AAAA 记录。

对于 `mapi` 服务端请求：

1. 从通过验证的公网地址中选择一个地址；
2. 使用 cURL `CURLOPT_RESOLVE` 固定主机、端口和已验证 IP；
3. 禁止跟随重定向；
4. 保持 TLS 证书和主机名校验；
5. 不在验证后重新接受未经检查的新解析地址。

对于 `submit` 模式：

- 服务端在生成跳转 URL 前再次验证上游；
- 浏览器跳转仍由客户端重新进行 DNS 解析；
- 这是客户端跳转模式的固有限制；
- 相同主机名和生成时的 DNS/IP 回环检查仍必须通过。

### 5.5 共享 CDN 取舍

严格策略会拒绝以下情况：

- CXPAY 与外部上游使用不同域名；
- 两个域名在验证时解析到相同公网 IP；
- 两者有效端口相同。

共享 CDN 或共享反向代理可能因此产生误拒绝。

本设计接受该取舍，因为已明确选择“严格拒绝、无绕过”。

## 6. 调用位置

### 6.1 保存通道配置

`epay_generic::upchannel()` 必须调用 `EpayUpstreamGuard`。

验证失败时返回：

```text
code = -1
msg = 外部易支付上游不能指向当前 CXPAY 实例
```

不得保存无效配置。

### 6.2 实际下单

`epay_generic::pay()` 必须在以下操作前重新验证：

- 生成 `/submit.php` 跳转地址；
- 请求 `/mapi.php`；
- 返回支付 URL 或二维码内容。

运行期验证失败时：

- 不生成可用支付链接；
- 不发送 HTTP 请求；
- 不吞掉安全异常后回退到 submit；
- 由统一支付错误流程记录并返回失败。

只有普通 MAPI 网络故障可以回退到 submit；安全校验失败不能回退。

### 6.3 回调验签

本次不改变 `notify()` 的 MD5 验签协议。

## 7. 墓碑和注册保护

在 `RemovedPaymentDrivers::CODES` 中加入：

```text
qqpay_epay
```

墓碑必须覆盖：

- `PaymentManager` 内置驱动发现；
- 动态注册；
- 插件注册；
- 管理员通道保存；
- 商户通道保存；
- 套餐允许通道清理；
- 公开驱动列表。

不得只依赖“源码目录不存在”。

## 8. 数据迁移

### 8.1 复用现有清理框架

继续使用：

```text
database/migrations/20260805_remove_legacy_payment_drivers.php
```

以及：

```text
app/service/LegacyPaymentDriverCleanupService.php
```

现有机制继续保持：

- 默认 dry-run；
- 仅精确 `--apply` 执行；
- DDL 与事务性 DML 分离；
- `lockForUpdate`；
- 待支付订单阻断；
- 非敏感归档；
- 轮询组关联清理；
- 套餐允许通道清理；
- 活动通道删除；
- 重复执行幂等。

由于该迁移已在当前生产环境执行过，加入 `qqpay_epay` 后必须再次执行 dry-run，并根据输出决定是否执行 `--apply`。

### 8.2 待支付订单保护

若任何 `status=0` 的订单引用 `qqpay_epay` 通道：

- dry-run 显示数量；
- `--apply` 拒绝执行；
- 不归档；
- 不删除关联；
- 不修改套餐；
- 不删除通道。

必须先完成、关闭或迁移这些待支付订单。

### 8.3 归档内容

继续归档以下非敏感元数据：

- 原通道 ID；
- 商户 ID；
- 支付分类；
- 标题；
- `c_type`；
- 备注；
- 权重；
- 单笔和日限额；
- 统计金额和数量；
- 在线状态；
- 启用状态；
- 归档原因；
- 归档时间。

明确禁止归档：

- `config`；
- PID；
- KEY；
- token；
- 密钥；
- Cookie；
- 会话数据。

### 8.4 归档原因

`qqpay_epay` 使用归档原因：

```text
superseded_by_epay_generic
```

已有五个永久移除驱动继续使用原归档原因：

```text
removed_placeholder_or_shared_token_driver
```

清理服务需要根据通道代码选择归档原因，而不是对所有驱动使用同一个常量。

### 8.5 历史数据

保留：

- `cx_order.channel_id`；
- `cx_callbill.channel_id`；
- 其他历史审计数据。

删除活动通道记录不应级联删除历史订单或历史账单。

## 9. 后台呈现

驱动市场中：

- 不显示 `qqpay_epay`；
- 显示 `epay_generic`；
- 名称显示“外部易支付上游（可选）”；
- 描述明确其第三方上游角色。

收款通道配置页：

- 不自动创建 `epay_generic` 实例；
- 没有实例时不显示其通道卡片；
- 公开驱动总数动态显示 5；
- 已有通道数量按数据库实例实时统计。

## 10. 错误处理

### 10.1 配置错误

示例：

- API URL 无效；
- PID 为空；
- KEY 为空；
- mode 非 `submit` 或 `mapi`。

返回可操作的配置错误，不保存数据。

### 10.2 安全错误

示例：

- 指向当前站点；
- 指向本机服务；
- 指向私网；
- DNS 无法验证；
- 与本站解析 IP 和端口重合。

安全错误必须失败关闭，不能自动回退。

### 10.3 普通网络错误

仅 MAPI 请求中的普通网络错误允许回退至已经通过安全验证的 submit 模式。

- 动态注册拒绝；

### 11.2 源码清理测试

验证：

- `app/payment/Drivers/QqpayEpay/` 不存在；
- 代码库中没有生产引用；
- 测试夹具不再依赖该驱动。

### 11.3 元数据测试

验证 `epay_generic`：

- code 仍为 `epay_generic`；
- 标题为“外部易支付上游（可选）”；
- 描述包含“第三方”和“不是下游接口”的含义；
- 支持支付宝、微信和 QQ 三种支付类型；
- 默认不会生成数据库通道实例。

### 11.4 回环保护测试

覆盖：

- 相同域名拒绝；
- host 大小写差异仍拒绝；
- host 末尾点差异仍拒绝；
- 相同 IP 和相同端口拒绝；
- 不同域名解析到本站 IP 时拒绝；
- localhost 拒绝；
- IPv4 环回拒绝；
- IPv6 环回拒绝；
- RFC1918 私网拒绝；
- 链路本地地址拒绝；
- 保留地址拒绝；
- URL 用户名或密码拒绝；
- DNS 无结果时拒绝；
- `APP_URL` 缺失时拒绝；
- 合法外部公网地址通过。

DNS 测试必须使用可注入解析器或测试替身，不能依赖真实公网 DNS。

### 11.5 驱动运行测试

覆盖：

- submit 模式正常生成已签名 URL；
- mapi 模式正常返回二维码或支付链接；
- mapi 普通网络错误回退 submit；
- 安全错误不回退；
- MAPI 请求绑定已验证 IP；
- 回调验签行为不回归。

### 11.6 迁移测试

覆盖：

- dry-run 不修改活动数据；
- 待支付订单阻止 apply；
- 无待支付订单时归档；
- 归档中不包含 config；
- 归档原因正确；
- 轮询组关联删除；
- 套餐 CSV 中移除 `qqpay_epay`；
- 活动通道删除；
- 历史订单保留；
- 历史账单保留；
- 第二次执行全部为零。

### 11.7 完整回归

执行完整 PHPUnit 测试套件。

不得以定向测试代替完整回归。

## 12. 发布步骤

1. 备份数据库。
2. 部署代码但暂不启用外部上游。
3. 重启 Workerman。
4. 执行完整 PHPUnit 回归。
5. 执行迁移 dry-run。
6. 检查 `qqpay_epay` 通道和待支付订单数量。
7. 待支付订单为零时执行 `--apply`。
8. 再次执行 dry-run，确认所有数量为零。
9. 浏览器强制刷新管理后台。
10. 确认公开驱动总数为 5。
11. 确认 `qqpay_epay` 不存在。
12. 确认 `epay_generic` 显示新名称。
13. 保持外部易支付上游默认未创建、未启用。
14. 推送分支并更新 PR。

## 13. 验收标准

- `qqpay_epay` 源码被删除；
- `qqpay_epay` 被永久墓碑阻止；
- 公开列表没有 `qqpay_epay`；
