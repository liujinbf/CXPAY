# CXPAY 本地与云端协同开发与软件发布全局规范

## 1. 架构定位：本地站点 + 官方云端授权中心

CXPAY 采用「本地授权实例 + 官方云端授权中心（Cloud Center）」架构：
- **云端中心 (Cloud Portal)**：负责插件市场（CloudPlugin）、实例授权与签名鉴权（Ed25519 License）、官方加密资产存储与分发；
- **授权主站 (Authorized Instance)**：客户私有化部署实例，通过 `CloudInstanceClient` / License Key 连接官方云端获取授权与插件，具备完全独立的多商户运营能力；
- **终端客户端 (Clients)**：包含 Android 监控助手（`CXPayAssistant`）、PC 店员/小账本监控端等。

---

## 2. 客户端软件与驱动开发发布铁律

### ① 必须经过代码混淆与加密加固
- 所有对外发布的客户端软件（Android APK、PC 挂机助手可执行程序）和高级核心驱动，**严禁明文/未加固直接分发**；
- Android APK 必须开启 ProGuard 混淆、签名并接入加固流程；
- 软件与插件包必须通过官方签名与加密打包工具生成发行资产。

### ② 统一托管于官方云端授权分发源
- 官方编译并加密加固后的软件安装包与驱动，**统一上传至官方云端授权站 / 云存储分发源**；
- 授权站点通过官方云端接口获取最新版本、更新日志与安全下载地址，确保源码授权出库后，全网其他独立部署站点均能无缝下载与热升级。

### ③ 严禁写死单个测试站点的本地域名
- 代码与静态页面中严禁硬编码临时测试域名（如写死特定测试 IP 或测试域名）；
- 涉及下载与接口请求时，必须通过：
  1. 官方统一云端分发接口/配置源；
  2. 或使用动态主站环境变量 `window.location.origin` / `getBaseUrl()` 自适应兜底。

---

## 3. 插件开发与授权流程规范
1. 支付驱动插件遵循 `AbstractPersonalQrDriver` / `AbstractDriver` 标准契约；
2. 涉及收费或高级特性插件，必须在云端注册 `plugin_id` 并接入 `PluginLicenseService` 鉴权机制；
3. 本地站点一律通过 `PluginPackageInstaller` 从官方云端安全拉取与挂载。
